# #258 PDF extraction parity — production-readiness evidence

Date: 2026-11-27
Branch: `feat/258-pdf-parity` (base `origin/main` at #257)
Scope: native Rust PDF ingestion for `document_format = "pdf"` docs sources.

## Control basis

Engram retrieval did not contain the FedRAMP/OWASP control text; this is the
recorded escalation (same basis as the #244 Phase A audit). Control IDs are
mapped at chapter level from:

- NIST SP 800-53 Rev.5 (DOI 10.6028/NIST.SP.800-53r5)
- NIST SP 800-53A Rev.5 assessment procedures
- OWASP ASVS 5.0.0

## Preserved Python contract

`src/engram/flows/configured.py:271-296` (`process_pdf_file`):

- pages are numbered 1-based in source order; blank pages are omitted without
  renumbering later pages;
- each participating page renders as `--- Page {n} ---\n\n{text}` and pages
  join with `\n\n`;
- a whitespace-only render returns before `_retain_document`;
- ids, Markdown chunking, synthesis metadata, tags, and the file timestamp use
  the same `_retain_document` path as Markdown.

## Implementation

- `config.rs`: `document_format` is parsed into `DocumentFormat`
  (`markdown`/`pdf`, with the Python `md`/case aliases) on `DocsSource`; the
  startup rejection is removed; unknown formats still fail validation.
- `pdf.rs`: pure-Rust `pdf-extract` 0.12 (MIT) parses bytes already read by the
  scanner. Extraction is page-ordered, catches dependency panics, normalizes
  line edges/blank lines to pdfplumber's `extract_text` shape, and renders the
  Python marker contract.
- `scan.rs`: chooses Markdown decode or PDF rendering per source; the manifest
  hash is SHA-256 of the rendered content (not PDF bytes), so identical text is
  not a change; `size_bytes` stays the original file size.
- `runtime.rs`: the ledger `sources.document_format` now records the source's
  real format instead of the Markdown default.
- No OCR, no Python/pdfplumber subprocess, no resident service, and no
  CocoIndex removal. Markdown behavior is unchanged.

## Known limits and residual risk

- Parity is pinned to committed fixtures. Multi-column, table, and rotated
  layouts may group lines differently from pdfplumber; the pure-Rust extractor
  does not reproduce pdfplumber's full layout algorithm. This is documented in
  `fixtures/pdf/README.md` and is the same class of heading-less chunk
  instability already accepted in `docs/COCOINDEX_DEPRECATION.md`.
- Scanned/image-only PDFs produce no text in either implementation; OCR remains
  out of scope.
- The scanner already reads whole files before parsing (pre-existing bound), so
  PDF decompression cost inherits that bound; no new size cap is introduced.
- Encrypted PDFs are rejected as an extraction error; the Python flow has no
  password path either.
- `pdf-extract` panics are caught, but a dependency that aborts the process
  instead of unwinding would still terminate the runtime; the release profile
  keeps `panic = "unwind"` (no `panic = "abort"` override).
