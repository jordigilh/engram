## Phase A results

### 1. Unit-tier coverage (SA-11; ASVS 4.0 V14.2 / 5.0 V14)

The business-logic unit gate now runs separately from the all-targets gate:

```bash
cargo llvm-cov -p engram-ingest --lib \
  --ignore-filename-regex '(http|store|sink|worker)\.rs' \
  --fail-under-lines 90
```

Result: **92.09% lines** (`91.86%` regions). The gate is an **aggregate over
every non-excluded lib file**; it is not an average of the feature files below.
The excluded files are I/O adapters: `http` (reqwest transport), `store`/`sink`
(Postgres and Hindsight clients), and `worker` (thread/slot supervisor). Their
behavior is covered by the HTTP and Postgres integration tiers.

New unit tests cover GraphQL error/rate-limit branches, missing pageInfo,
repeated cursors, null nodes, empty/updated timestamps, comment boundaries,
short headers, stream validation, and snapshot scan/reconciliation.

### 2. Board stability (SI-7, SI-11, SI-12)

`poll_board` now requires two identical full passes (title, description, and
ordered item identities) before replacing the canonical board document. Two
identical empty passes confirm a genuinely empty board; a changed pass returns
the transient `Unstable` error and applies nothing. `page_count` records both
passes. Tests cover a stable board, a changed second pass, confirmed empty,
null nodes, and missing project/title.

### 3. Migration 0006 recovery (CM-3, CP-9)

- The migration guard now inspects `sources_source_kind_check` and fails when a
  recorded version 6 lacks `github_discussion`/`github_board`.
- A Postgres test simulates a v5 constraint recorded as v6 and asserts
  `MigrationMismatch`.
- Rollback SQL is recorded in the migration header: stop writers, back up,
  remove discussion/board sources, restore the v5 constraint, delete version 6,
  then rerun `migrate()`.
