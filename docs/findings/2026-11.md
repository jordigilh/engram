# Research Findings — November 2026

## 2026-11-26: A healthy zvec-grep daemon was invisible because the native LaunchAgent used a private `ZVEC_GREP_HOME`

**Symptom.** `zg --server status` printed `Server: stopped` and
`zg --index --mode server` failed with `resident daemon is not ready` in 0.04s,
while `http://127.0.0.1:7999/mcp` answered normally. Exporting
`ZVEC_GREP_HOME=/Users/jgil/.local/zvec-grep-native/home` made the same binary
report `ready`.

**Cause.** zg resolves daemon state from `ZVEC_GREP_HOME ?? ~/.zvec-grep`. The
native launchd job (`io.vectorize.zvec-grep-native`) ran with a private home and
the model cache, but no caller inherited either variable. During the MLX binary
swap this produced a false "server is down" and an aborted index run before the
environment was discovered. The deployment is an Engram choice: `zvec-grep` has
no `zvec-grep-native` reference and documents `~/.zvec-grep` as its default.

**Applied workaround (host-local).** A `sh` shim at `/Users/jgil/bin/zg`
defaulted both variables and exec'd the real binary. It unblocked the host but
was untracked and would be lost on reinstall, and it left two shells with the
same `PATH` seeing different daemon state.

**Durable resolution.** The native job moves to the default home with no
`ZVEC_GREP_HOME` at all. Preflight showed there was nothing to merge: the
workspace registry was already at `~/.zvec-grep/workspaces.json`, workspace
indexes stay under each repo's `.zvec-grep`, and the private home held only
`daemon/instance.lock` and `daemon/logs/server.log`. The repo now ships the
native launchd template plus `engram-zvec-grep-native`
(`install | verify | uninstall | lock-repair`), which refuses foreign or
unverifiable state, never mutates a lock outside `lock-repair`, keeps
timestamped backups, and verifies the loaded job against the deployed render and
a clean-environment `zg --server status --check-ready`.

**Lesson.** Deployment state that a CLI resolves from the environment must be
the same state the service writes by default; a wrapper that patches every
caller hides the split rather than closing it. See
[docs/NATIVE_ZVEC_GREP_HOME.md](../NATIVE_ZVEC_GREP_HOME.md) for the contract
and cutover procedure, and jordigilh/zvec-grep#101 for the tool-side
diagnosability follow-up.
