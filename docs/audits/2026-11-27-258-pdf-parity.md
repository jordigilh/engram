# #258 PDF extraction parity — production-readiness evidence

Date: 2026-11-27
Branch: `feat/258-pdf-parity` (base `origin/main` at #257)
Scope: native Rust PDF ingestion for `document_format = "pdf"` docs sources.

## Control basis

Engram retrieval did not contain the FedRAMP/OWASP control text; this is the
recorded escalation (same basis as the #244 Phase A audit). Control IDs are
mapped at chapter level from:

- NIST SP 800-53 Rev.5 (DOI 10.6028/NIST.SP.800-53r5)
- NIST SP 800-53A Rev.5 assessment procedures
- OWASP ASVS 5.0.0

## Preserved Python contract

`src/engram/flows/configured.py:271-296` (`process_pdf_file`):

- pages are numbered 1-based in source order; blank pages are omitted without
  renumbering later pages;
- each participating page renders as `--- Page {n} ---\n\n{text}` and pages
  join with `\n\n`;
- a whitespace-only render returns before `_retain_document`;
- ids, Markdown chunking, synthesis metadata, tags, and the file timestamp use
  the same `_retain_document` path as Markdown.

## Implementation

- `config.rs`: `document_format` is parsed into `DocumentFormat`
  (`markdown`/`pdf`, with the Python `md`/case aliases) on `DocsSource`; the
  startup rejection is removed; unknown formats still fail validation.
- `pdf.rs`: pure-Rust `pdf-extract` 0.12 (MIT) parses bytes already read by the
  scanner. A preflight loads the document, applies the same empty-password
  decryption as pdf-extract, validates every page with lopdf's strict content
  parser (the lenient parser silently truncates corrupt streams), caps
  FlateDecode expansion, catches dependency panics, normalizes line edges/space
  runs/blank lines to pdfplumber's `extract_text` shape, and renders the Python
  marker contract.
- `scan.rs`: chooses Markdown decode or PDF rendering per source; the manifest
  hash is SHA-256 of the rendered content (not PDF bytes), so identical text is
  not a change; `size_bytes` stays the original file size.
- `runtime.rs`: the ledger `sources.document_format` now records the source's
  real format instead of the Markdown default.
- No OCR, no Python/pdfplumber subprocess, no resident service, and no
  CocoIndex removal. Markdown behavior is unchanged.

## Evidence by control objective

### SI-10 information input validation; ASVS 5.0 V1/V2 (encoding, validation)

- `config::tests::accepts_pdf_format_and_defaults_to_markdown` proves `pdf`
  (including case alias), omitted defaults, and `docs_format = "md"`.
- `config::tests::rejects_unknown_formats` proves unsupported formats still
  fail with the Python-compatible message.
- `scan::tests::malformed_pdf_aborts_the_snapshot`,
  `pdf::tests::corrupt_page_content_is_rejected_instead_of_partially_ingested`,
  `pdf::tests::malformed_pdf_is_an_error_not_a_panic`, and
  `pdf::tests::panic_boundary_reports_panic` prove malformed/untrusted PDF
  structure becomes a source-level error, not a crash or partial snapshot.
  Page content is decoded with lopdf's strict parser because the lenient
  parser silently truncates after a corrupt operator; a truncated page would
  otherwise be ingested and delete the chunks it no longer contains.
- `pdf::tests::decompression_bomb_is_rejected_before_extraction` and the
  stream preflight cap decompressed FlateDecode streams (64 MiB per stream,
  256 MiB per document) before extraction; a small bomb becomes
  `PdfError::Extract` instead of worker OOM.
- `runtime_postgres.rs::corrupt_pdf_skips_the_source_and_leaves_the_manifest_untouched`
  proves the runtime reports `Skipped` (matching the existing read-failure
  policy for a whole source snapshot), emits no retain, and leaves the manifest
  unchanged. Quarantining one bad file while applying the rest of the source is
  a ledger-level policy change and stays out of #258.
- `scan::tests::pdf_sources_ignore_markdown_decode_semantics` proves the
  processor follows the configured source format, not file content.

## Known limits and residual risk

- Parity is pinned to committed fixtures. Multi-column, table, and rotated
  layouts may group lines differently from pdfplumber; the pure-Rust extractor
  does not reproduce pdfplumber's full layout algorithm. This is documented in
  `fixtures/pdf/README.md` and is the same class of heading-less chunk
  instability already accepted in `docs/COCOINDEX_DEPRECATION.md`.
- Scanned/image-only PDFs produce no text in either implementation; OCR remains
  out of scope.
- FlateDecode streams are inflated with a hard cap during preflight, so a
  classic decompression bomb is rejected before extraction. Uncommon
  non-FlateDecode filters are only capped by compressed size before extraction;
  the extractor's own inflation of those filters is not independently bounded.
- Password-protected PDFs (non-empty user password) are rejected as an
  extraction error. Empty-user-password encrypted PDFs are decrypted the same
  way pdf-extract/pdfplumber do; no password input path exists in either flow.
- `pdf-extract` panics are caught, but a dependency that aborts the process
  instead of unwinding would still terminate the runtime; the release profile
  keeps `panic = "unwind"` (no `panic = "abort"` override).
- A rejected PDF (corrupt, unsupported, or over the stream cap) skips the whole
  source snapshot for that pass, exactly like an unreadable file. Per-file
  quarantine while applying the rest of the root is a larger ledger policy and
  is explicitly out of scope for #258.
