# PDF parity fixtures (issue #258)

- `guide.pdf` is generated by `make_fixture.py` (standard library only, no
  embedded font). It has four pages: page 1 and page 3 contain text, page 2 is
  blank, and page 4 contains only spaces. Text covers Latin-1 accents, an en
  dash, PDF-escaped delimiters, an indented line, and a paragraph gap.
- `blank.pdf` is generated by the same script. No page has non-whitespace text.
- `goldens.json` is generated by `generate_goldens.py` from the **real** Python
  path: `pdfplumber` per-page text, the exact `process_pdf_file` rendering, and
  every retain call `_retain_document` would send (ids, chunks, synthesis
  metadata, tags, timestamp).

Regenerate the PDFs (no dependencies):

```bash
python3 rust/crates/engram-ingest/fixtures/pdf/make_fixture.py
```

Regenerate the oracle with the deployed flow interpreter (Python 3.14,
pdfplumber, sklearn/networkx):

```bash
PYTHONPATH=src ~/.engram/venv/bin/python \
    rust/crates/engram-ingest/fixtures/pdf/generate_goldens.py
```

`tests/pdf_parity.rs` checks the fixture SHA-256 against the goldens, then
compares rendered content and planner output byte-for-byte. Review any
`goldens.json` diff together with the Python source or fixture change; CI does
not regenerate it because the oracle needs the flow venv.

## Scope and known limits

Parity is pinned to these fixtures, which exercise the contract in
`src/engram/flows/configured.py:271-296`: page markers, one blank page, a
whitespace-only page, non-ASCII text, line trimming, and paragraph-gap
collapse. Both implementations extract only embedded text; scanned/image-only
PDFs yield no retain calls and OCR remains out of scope.

Layout-heavy PDFs (multi-column, tables, rotated text) may still group lines
differently between pdfplumber and the pure-Rust `pdf-extract` crate. The Rust
rendering normalizes line edges and removes empty lines to match pdfplumber's
`extract_text` shape, but it does not reproduce pdfplumber's full layout
algorithm.
